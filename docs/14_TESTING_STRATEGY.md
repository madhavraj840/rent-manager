## 1. Priorities

Money and sync bugs are the costliest failures (R-01, R-10). Test effort is therefore weighted as follows:

1. **Financial engine** (shared vectors on Kotlin, TypeScript and SQL)
2. **Sync protocol** (scenario tests with simulated devices + Android offline tests)
3. **Authorization and isolation** (table-driven, every endpoint × every role)
4. Commands and constraints (integration tests on a real PostgreSQL)
5. Critical UI flows (few, end-to-end)

## 5. CI gates

| Gate | Blocks merge when |
|---|---|
| Lint + typecheck + unit | Any failure |
| Financial vectors (Kotlin, TS, SQL) | Any vector fails or a vector is missing in one implementation |
| DB + integration + API + sync simulator | Any failure |
| PERM/SEC automated suites | Any failure, or a route without an authz declaration |
| Coverage (informational) | `domain/` modules < 90% line coverage |

Nightly: Android UI tests on emulator, Playwright, performance smoke. Before each release: manual checklist (§6).

## 6. Release checklist (manual)

1. Fresh install on Android 8, 11, 14 and the latest version (low-end + mid-range device): sign in, onboarding, first tenancy.
2. **Upgrade from the previous release with pending offline ops** → ops still sync.
3. OFF-TEST-001 in a real no-signal location (basement or airplane mode).
4. Receipts, statement and settlement PDFs render with ₹, Hindi/Arabic names, and long property names.
5. Dark mode and 200% font scale on key screens.
6. Account deletion in app and on web.
7. Backup restore drill (quarterly) passed within the last 3 months.
8. Play Store data safety form matches actual data collection (11 §2).

## 7. Beta programme

5–10 landlords (mix of `small-landlord` and `agency` profiles) for 6 weeks: weekly check-in, in-app "Send feedback" (email), watch sync rejection rates and balance-related reports daily. The exit criteria are the success metrics in 01 §14 and zero open money bugs.
